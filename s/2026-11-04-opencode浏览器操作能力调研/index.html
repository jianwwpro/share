OpenCode 能力分析

OpenCode 核心能力

根据 OpenCode 技能文档，OpenCode 主要提供以下能力：

  1. 配置管理: JSON/JSONC 配置文件支持
  2. MCP 服务器: 可配置外部服务器
  3. 插件系统: 可扩展功能
  4. API 接口: HTTP API 和 TypeScript 客户端
  5. 会话管理: 多会话支持
  6. 工具执行: 可通过插件和工具扩展能力

OpenCode 直接操作浏览器的可能性

1. 原生支持

OpenCode 本身不直接提供浏览器自动化功能。核心功能集中在：

  • AI 对话管理
  • 文件系统操作
  • 代码编辑
  • 终端命令执行
  • 配置管理

2. 通过插件扩展

OpenCode 有插件系统，理论上可以开发浏览器操作插件：

  • 可创建自定义插件
  • 插件可以添加新工具
  • 但需要自行开发实现

3. 通过 MCP 服务器

可通过 MCP (Model Context Protocol) 服务器集成浏览器自动化：

  • 配置外部 MCP 服务器
  • 服务器可提供浏览器操作工具
  • OpenCode 通过 MCP 调用这些工具

4. 通过现有工具调用

可通过现有的 shell 工具间接操作浏览器：

  • 使用 shell 工具调用 Node.js 脚本
  • 脚本中使用 Puppeteer/Playwright
  • 但这需要手动安装依赖

实现方案建议

方案1: 安装浏览器自动化库（推荐）

# 安装 Puppeteer
npm install puppeteer

# 或安装 Playwright
npm install playwright

然后在 OpenCode 中通过脚本调用：

// 示例：使用 Puppeteer 打开网页
const puppeteer = require('puppeteer');

async function openBrowser() {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  await page.goto('https://example.com');
  // 其他操作...
  await browser.close();
}

方案2: 创建 OpenCode 插件

创建自定义插件提供浏览器操作工具：

// 插件示例
export const browserPlugin: OpenCodePlugin = {
  name: 'browser-automation',
  tools: [
    {
      name: 'open_browser',
      description: '打开浏览器并导航到指定URL',
      // 实现细节...
    }
  ]
};

方案3: 配置 MCP 服务器

寻找或创建浏览器操作的 MCP 服务器：

{
  "mcp": {
    "servers": {
      "browser-automation": {
        "command": "node",
        "args": ["browser-mcp-server.js"],
        "env": {}
      }
    }
  }
}

限制和注意事项

技术限制

  1. 浏览器依赖: 需要本地安装浏览器
  2. 权限问题: 可能需要额外的系统权限
  3. 资源消耗: 浏览器实例会占用内存
  4. 稳定性: 自动化脚本可能不稳定

OpenCode 限制

  1. 无原生支持: 需要额外配置
  2. 插件开发: 需要开发技能
  3. MCP 学习曲线: 需要理解 MCP 协议

安全考虑

  1. 浏览器权限: 自动化脚本有较大权限
  2. 数据安全: 注意敏感信息泄露
  3. 资源访问: 控制可访问的网站范围

结论

可行性评估

  • 直接支持: ❌ OpenCode 不原生支持浏览器操作
  • 间接实现: ✅ 可通过插件、MCP 服务器或脚本调用实现
  • 复杂度: 中等（需要额外配置和开发）

推荐路径

对于简单用例，建议：

  1. 安装 Puppeteer 或 Playwright
  2. 创建 Node.js 脚本 处理浏览器操作
  3. 通过 OpenCode 的 shell 工具 调用脚本
  4. 逐步封装 为更易用的工具

对于复杂需求，建议：

  1. 开发 OpenCode 插件 提供专门的浏览器工具
  2. 或配置浏览器操作的 MCP 服务器
  3. 集成到工作流 中
